## Goals / Non-Goals

**Goals:** 讓多趟遠征有可辨識的敘事與戰術差異；優先展開未用原典素材；保持純本機、可序列化、可續玩；以獨立的內容、行為、真人、飛航證據作驗收。

**Non-Goals:** 不更換題材、不增加第四職業、不實作完整技能樹／程序地圖／回訪房間／新永久升級／新異象／所有原典章節／全面 UI 或美術重做。本輪維持七個敵人定義、六個永久升級、三個異象及兩個掉落表；深度由既有遭遇與兩件新遺物提供。此 task 只交付 OpenSpec 文件。

## Decisions

### 1. 三個內容單元與固定匯流點

| 單元 | 原典參照位置（依 repo 原典索引） | 玩家決策與持續後果 | 匯流／界線 |
| --- | --- | --- | --- |
| 森林盟約 → 三日圍困 | 613–622、639–653 | 履約護送或取用林中物資；盟約影響圍困一次補給支援。三個白晝、兩個中間夜晚分別選守鼻、保護路人、紮營等取捨；成功連續阻止進食三日才取得異鋼 | `camp`／`marsh` 到 `forge`；保留既有壓縮遭遇為明示改編的快速路線，圍困線沒有用 HP 打死龍鱷的出口 |
| 鋼門 → 堡內二選一路線 | 654–680、697–722 | Porte Resonant 引出龍吠；舉劍宣名提高可見警戒，影響後續代價。選駱駝衛隊／兩百侍者的交涉線，或火眼夢女／牆中狼的辨夢線；不同情報分別影響守龍或終戰的提示／準備資源 | `gate` 後分流，`abyss` 前匯流；單趟不能兩線全拿，不新增可自由走動的城堡 |
| 歸鄉記錄 | 786–797 | 依本趟已見線索呈現英雄、熱病或人物不存在的相互矛盾記錄，保存已見版本，指向另一趟尚未探索的路線 | 既有勝利結算先完成，再顯示尾聲；尾聲不另發勝利／見聞貨幣 |

不使用本輪以外的四十行咒語組合、Thok/Lunk 拆分與鐵窗囚物。將其加進提案雖能拉高篇幅，卻增加新系統與無法驗收的工作量。

三日圍困是單向展開的五個時段，不讀實際時間。每個時段至少兩個有不同後果的選擇；零補給仍有明示生命代價的保護／守候選項或撤離。讓龍鱷吃到人即使圍困失敗，返回既有撤離結局；不重設第一日刷資源，不產生異鋼。生命歸零進戰敗。森林盟約有支援／未支援兩種後續結果，不建通用陣營好感系統。

警戒採單趟二值 flag，僅影響本輪路線的明示代價；不新增全地圖威脅模擬。每條堡內路線至少四個實質場景、三次有效決策，以及一個在另一場景才兌現的後果。原典的衛隊潰逃、傳話與火眼意象可取用；警戒、傳話失真玩法、資源獎勵與可選結局均須註記為原創改編。

### 2. 內容量是產製門檻，不是時數估算

實作建立可從 `story.ts` 對照的內容清單，記錄 baseline ID、新增／改寫 ID、路線、事件池、provenance、前置及後果 ID。淨增至少 24 個實質節點與 60 個選項，總數至少 62／151；建議上限為淨增 32／84，超出需重新評估本 change 範圍。改名、拆段、空白過場、重複選項和單純數值換皮不算淨增實質內容。

兩個池各增加四個事件，總計 16 件；新八件包含在 24 節內，不重複計算。每件至少兩個有不同資源／線索／路線結果的選項，新八件至少四件有跨節點後果。保持每池每趟僅抽一次，事件是插入 DAG 的節點，不改為牌庫或無限遭遇。若素材自然需要多節事件，以一個事件入口 ID 計事件數。

保留 `source: 'sacnoth' | 'original'` 契約：混合場景的 note 明列原典素材及新增玩法，純原創情節不得因使用原作名稱而標成原作。每個採用素材記錄 repo 原典索引的行段／原文定位，實作撰寫新細節時回查英文原文。閱讀稿只用 `npm run rpg:text` 產生。

### 3. 每職業一個專精選擇，不增加技能樹

`forge` 提供每職業二選一專精，這趟鎖定，戰敗／新局重選；三職業所有選項首次遠征即可使用，無永久見聞門檻。保留現有五種戰鬥按鈕，專精改變 skill/guard 的規則與說明。下表為實作起始規則，數值可在測試階段調整並記錄，不能把兩側調成相同作用。

| 職業 | 直接型 | 準備型 |
| --- | --- | --- |
| 戰士 | 破甲：保留現有忽略護甲重擊 | 反擊：格擋受到攻擊後取得一次準備；下次技能消耗準備獲傷害加成，但無準備時技能不忽略護甲 |
| 法師 | 餘燼：保留現有技能與當回合減傷 | 蓄咒：格擋取得一次準備，下次技能魔力成本降低（最低 1）且提高傷害，但失去原技能的當回合減傷 |
| 遊俠 | 穿隙：保留現有忽甲技能與減傷 | 窺隙：格擋取得一次準備，下次技能遇 exposed 意圖額外增傷；無破綻時不獲該增傷，且失去原技能的當回合減傷 |

準備只是一個 `battle.prepared` 布林，不疊層；取得後維持至下一次技能消耗或戰鬥結束，致勝、撤離與下一場不繼承。效力由引擎計算，畫面能讀到有無準備、消耗與預期規則；非法／過期行動不得取得或消耗準備。

新增兩件原創遺物作可選的固定支線獎勵：盟約繩結強化 guard 但降低普攻，燭淚鏡強化 exposed 時的技能但提高技能魔力成本。只能裝備其中一件，允許不裝備；取得第二件時由玩家選擇替換，不默默覆蓋。沿用 inventory 保存所有權，`run.equippedRelic` 保存裝備選擇，戰鬥外調整且無消耗／亂數。先明列修正，再與既有符文、異象、月石共同計算；魔力成本最終下限 1、傷害下限 0，最終數值以 catalog 為唯一來源。兩張原有掉落表維持原有結果，避免為了取得流派被迫反覆刷 seed。

守龍的尾擊及 Gaznak 的移首手腕，各至少一項條件規則：守龍重尾擊可由 guard 抵消其額外穿透，Gaznak 移首窗口才使 skill 獲得弱點加成。每項必須有意圖文字與可見後果，不能只增加 HP／傷害。不更動「只有 Sacnoth 能殺 Gaznak」的主線鑰匙，也不要求新專精／遺物才能通關。

### 4. 繼續由純引擎擁有狀態

新增狀態限定為專精、裝備遺物、戰鬥準備及至多六個敘事記錄 ID。圍困進度由不同 nodeId 表示，盟約、警戒、情報用列舉 flags，不另外保存衍生天數／異象。`profile.tales` 是去重 ID 集，記錄內容由 `story.ts` 提供；不存整段閱讀稿、不等同現有貨幣 discoveries。新 tales 在抵達相應結果時寫入，失敗／撤離保留，重複遇見不發永久貨幣。

`run.random` 仍是事件、掉落、戰鬥唯一 PRNG；新版本不保證與 v1 seed 同結果，但同 v2、seed、完整起始 profile／配置、行動序列必須相等。異象仍由 seed 推導。事件候選固定依資料陣列順序抽樣，每次接受的抽取只前進一次，選出的事件 nodeId 保存；呈現、匯出、裝備切換、讀檔和拒絕行動不抽亂數。

`revision` 延續每次接受行動加一；故事消耗、戰鬥、專精、裝備、見聞及結局都由 reducer 決定。內容驗證須覆蓋 DAG、池邊、列舉參照、條件／負資源成本、唯一物品、每個可達狀態的合法出口；不能只以圖的可達性證明資源可行。

### 5. 不讓換版抹掉永久成果

使用 schema 2 + `nightmare-fortress-2`，維持同一儲存 key。凍結 v1 驗證所需的列舉／能力公式與代表性 fixture，在 persistence 邊界辨識「已知合法 v1」，不保留第二份可執行舊故事或整套引擎。新 run 欄位缺漏或不一致不得自行補猜；v2 的非空 profile + `run: null` 是合法的遠征外狀態。

| 輸入 | 行為 |
| --- | --- |
| 空儲存 | 建立 v2 空 profile |
| 合法 v2 | 原狀續接，含完整 PRNG、配置、戰鬥準備 |
| 合法 v1，含故事／戰鬥／已結束／空局 | 顯示轉換預覽、可複製原始 JSON，停止自動寫入；明示保留永久成果，進行中遠征將退休 |
| 玩家確認 v1 轉換 | 原樣保留 insight、victories、expeditions、六升級與五舊 discoveries；tales 為空、run 為 null，不發撤離／勝利／補償獎勵；revision 加一，完成 v2 驗證後一次 setItem |
| 拒絕、取消或尚未確認 | 留在恢復畫面，原始值不變，可複製資料；不開始會覆蓋舊資料的新局 |
| 損毀、未知版本、非法 v1 profile/run | 保留 raw、停止寫入，沿用明示重建流程；不得從非法片段猜測可轉移財產 |
| 初次讀取失敗／轉換寫入失敗 | 維持 readUnavailable／migration pending 與可複製 raw；不宣稱成功，後續 render 不自動重試覆寫 |

轉換是明示的資料操作，與遠征結算分離。重載已寫入 v2 不再轉換；連按確認使用 pending 狀態／revision 防重入。玩家可在覆寫前複製備份；原 key 的 raw 僅在明示轉換成功時被新資料替換。沒有自動降版：若 rollback 到舊 bundle，舊版應將 v2 保留為 incompatible，不清除；恢復 v1 只能由玩家使用先前自行保存的 raw，不承諾把新進度降轉。

### 6. 驗收採四層證據

**內容／路線矩陣**：至少 12 條具名可完成腳本，覆蓋 3 職業 × 2 專精 × 2 堡內路線；每組用同一凍結清單的 6 個 seeds（0–5）執行，共至少 72 趟，均可從無永久升級的新 profile 到達勝利。矩陣涵蓋圍困及快速路線、三異象與兩件遺物；另有資源不足、圍困失敗、戰敗、撤離腳本。腳本可依規則調整行動，必須記錄版本與完整決策，不能開發測試專用作弊入口。另掃描 seeds 0–255，在固定抽取前綴下覆蓋全部 16 事件；每個事件有正常引擎可達的種子及前綴證人。

有效決策定義為至少兩個當下合法選項，且會改變資源、戰術、路線、可用情報或結局；「繼續」不算，重複 attack/guard 輪轉不重複充數。每條 12 路線至少 12 次有效決策，其中至少四次效果在後一個以上場景才顯現。每職業的專精對照 fixture 須證明相同敵方意圖下至少兩種情境的合理操作／資源結果不同；不能只比較技能名字。

**真人 playtest**：至少六位未參與實作的繁中讀者，至少三位不熟悉本遊戲、三位有文字 RPG／roguelite 經驗（兩屬性可重疊），每職業至少兩位先試。每人比較凍結 v1 baseline 與候選 v2，各最多 180 分鐘、不同日進行；三人先 v1、三人先 v2，以降低學習偏差。使用獨立測試 profile，不影響個人正式存檔。自由決定何時停止；主持人不得要求反覆刷局來湊時間。願意續玩者第二趟改專精／堡內路線，第三趟自行選擇。記錄順序偏差，樣本不宣稱代表所有玩家。

每人每版本都由獨立的空 profile 開始，版本內自然取得的永久養成可用於重玩，不把 v1 的養成轉移進比較用 v2 profile。每人的兩版本使用相同初始職業與預先記錄的 seed 起點，後續自由選擇；不同版本不預期相同 seed 產生同故事。單份驗收報告必須是同一凍結候選 build，不能混合不同平衡版本湊六人門檻；改動影響指標時重測並保留前版結果。

人工計時／本機測試紀錄分開保存壁鐘與有效遊玩時間；有效時間包括閱讀、思考、戰鬥、整備，扣除背景、休息、故障等待及連續超過兩分鐘且玩家確認不在遊玩的閒置。引擎不讀時鐘，不加上傳 telemetry。每趟記錄 build SHA、contentVersion、裝置、profile／seed／行動、開始結束、勝敗／撤離、首次完成、有效決策、已見內容、停止原因、投入度 1–5、恢復損失。可匿名紀錄，不需要姓名。

敘事新鮮度以渲染實際出現的 `(nodeId, variantId, outcomeId)` 計數，排除隨機傷害數字、僅數值不同的戰鬥 log、無新因果的同義文字。重玩新內容比例 = 本趟首次見到且具新資訊／後果的單位數 ÷ 本趟全部不同敘事單位數。重複文字比例另以再次顯示的已讀敘事字元數 ÷ 本趟敘事字元數報告，兩者不可互換。內容清單給穩定單位 ID，人工審核防止改 ID 刷指標。

| 判定 | 必須通過的門檻 |
| --- | --- |
| 本輪擴寫有效（與本 change 內容／技術／飛航門檻一起使用） | v2 六人有效遊玩時間中位數 ≥120 分鐘；每人 v2 減 v1 的差值中位數 ≥30 分鐘；至少 4/6 自願開始第二趟且第二趟新內容比例 ≥30%；投入度中位數 ≥4/5；全部停止原因及重複文字比例公開在驗證紀錄 |
| 可以提出有限的「約三小時」主張 | 除上述條件，至少 4/6 在 180 分鐘時窗內自願有效遊玩 ≥150 分鐘；至少 4/6 自願進入第三趟且第三趟新內容比例 ≥20%；最後一趟投入度中位數 ≥4/5；飛航驗收通過。公開樣本與實測範圍，不寫「人人保證三小時」 |

未達本輪門檻則保留驗收任務未完成，先分析節奏／重複／流派失衡，在三個單元內迭代。若通過本輪而未過三小時門檻，允許本 change 完成，但 README／結案仍須標示三小時未證明並記錄下輪缺口；不得為追時數擴成全章節專案。

**飛航驗收**：凍結 production build，至少實際預計攜帶的手機／平板一台及桌面瀏覽器一種（桌面無飛航開關則關閉 Wi-Fi／拔網線），記錄 OS／版本、瀏覽器／模式與來源網址。先在 HTTPS 或 localhost 成功在線載入、等待 SW installed/activated 並受控、確認所有 precache 成功。關閉 Wi-Fi 與行動網路、確認原典外連無法開啟，完全關閉應用／瀏覽器後從原網址 `/#/rpg` 冷開；畫面、字型、像素圖與新故事皆須可讀。

在圍困夜間、已抽事件／掉落、已選專精／裝備、守龍準備狀態各保存一次，分別關閉重開並比較權威狀態；固定後續行動須與不中斷對照相同。至少一段連續 60 分鐘實際斷網，完成遠征、結算、新開第二趟且在每個已提交行動後無進度遺失；180 分鐘 playtest 中至少兩位全程使用通過安裝的離線裝置。重新上線更新 v1 → v2 後，再離線檢查明示轉換與新故事可用，快取清理不得觸及 localStorage 或同源其他 cache。

首次從未安裝不能離線開啟、儲存受阻／容量不足只能暫存，必須仍明示前提。重現先前「停 preview 後空白」情境，保存控制狀態與失敗／成功證據，區分安裝未完成、SW 生命週期、特定容器不支援；不推測既有原因。正式目標瀏覽器若失敗就阻擋飛航驗收，僅工具容器失敗且目標裝置成功則記錄支援界線。

**工程回歸**：依序完成內容驗證、RPG deterministic／持久化／mounted UI 測試、`npm test`、`npm run typecheck`、`npm run build`、`npm run rpg:text` 產物一致性、`git diff --check` 與 strict OpenSpec validation。360px 與桌面核對長選項、專精對比、原典／改編說明、恢復確認、鍵盤焦點與無水平溢出。正式產物預快取只能證明打包，不能替代實機冷開。

## Risks / Trade-offs

- [三個單元仍可能不到三小時] → 分開門檻、先測 baseline；用停止原因決定下一輪，不靠字數、拖慢動畫或強制刷局補時間。
- [準備型專精可能全優或太弱] → 每個選項有代價，六種配置可無升級通關，對照意圖及真人選擇紀錄；只調 catalog 數值仍需重跑受影響矩陣。
- [三日龍鱷與舊戰鬥矛盾] → 新圍困嚴守原典餓死規則，保留快速線但明示為壓縮改編，不聲稱舊 HP 戰鬥是原文規則。
- [換版必須退休進行中遠征] → 優先保住 profile，預覽與複製 raw 後明示確認；若要求舊局原樣玩完，需另一項舊引擎封存工作，不暗中擴充本輪。
- [小樣本／次序效應] → 分組交換測試順序、列個體結果與停止原因，主張限於實測條件。
- [新增片段稀釋單趟體驗] → 12 路線與真人新鮮度雙重驗證，事件總數不能替代真實遇見比例。
- [離線問題超出 RPG] → 最小修正既有 worker 並回歸其他遊戲；若是大型安裝策略重構則另列 change，本輪飛航 gate 保持未通過。

## Migration Plan

1. 固定 baseline SHA、v1 各 phase 快照、內容統計與真人基準方案。
2. 實作 v2 契約與相容性入口，再寫內容／戰術；未通過 parser 與 round-trip 前不導入自動保存新狀態。
3. 以已知 v1 合法／非法 fixtures 驗證轉換保留、取消、寫入失敗及重複確認，再更新 UI。
4. 生成閱讀稿、跑工程與路線矩陣、建立 production 候選；不以 dev server 驗收離線。
5. 完成真人／飛航證據，按門檻記錄通過或缺口；實作交付時更新既有 docs。提案 task 不部署、不提交。
6. 需要回退時保留原 key：舊 bundle 不能讀 v2 但不可覆寫；優先重新提供可讀 v2 的修正版。若玩家選用自行備份 v1，明示新版本進度不會合併。

## Open Questions

沒有阻擋 proposal 完成的產品選擇；本設計已選定上述單元、專精範圍與「保留 profile、退休舊局」策略。

未來實機驗收前需使用者提供預計帶上飛機的裝置、瀏覽器與開啟模式（一般分頁／加入主畫面），並安排六位真人或指定招募負責人。未取得這些資源時工程可以先完成，但真人與飛航項目保持未驗收，不能由 agent 假裝完成。

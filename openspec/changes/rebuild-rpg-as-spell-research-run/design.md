## Goals / Non-Goals

**Goals:** 讓每一回合與每一次遭遇都存在一個以上結果不同的合理行動；讓成長改變玩法而非只改變數值；讓單趟持續變化以取代重玩；保持純本機、可序列化、可離線續玩；以機器可重現的指標驗收，不依賴無法取得的真人資源。

**Non-Goals:** 不做程序地圖、不做跨趟永久養成、不加新職業、不新增敵人定義、不做雲端存檔、不引入網路或 LLM、不改其他遊戲、不主張任何遊玩時長。本輪不產出殘頁像素圖集。此 task 只交付 OpenSpec 文件。

## Decisions

### 1. 成長軸由職業換成法術書

三職業僅有六個數值差異（血、魔、攻、甲、技能消耗、技能傷害）與一項減傷布林，沒有任何獨佔機制；實測三者最佳打法完全相同。v2 的 `rpg-tactical-replay` 已要求「至少兩種情境顯示不同的合理操作，而非僅名稱或無條件傷害差異」，交付結果未達成該要求。

保留法師。法師是唯一一個施法成本（3）與格擋回魔（3）打平的職業，戰士與遊俠每次格擋淨賺 1 魔，資源曲線完全不緊。以法師為底盤時，魔力才有可能成為真資源。

砍除職業會移除唯一的趟間變化軸，因此必須同時補上趟內變化軸：法術書。若只砍不補，遊戲會更單調而非更深。

### 2. 殘頁、成分與韻：行數即等級

素材取自 `docs/rpg-source-reference.md:85` 明列未使用的原典項目：「咒語混合活語與死語、獵鯨呼喊、駱駝詛咒和象鳴，且每行押同一個怪韻」。原典結構直接對應機制，不需另造設定。

| 成分 | 原典對應 | 效果取向 |
| --- | --- | --- |
| 活語 | 活語 | 恢復、增益、護盾 |
| 死語 | 死語 | 對非實體生效、無視閃避 |
| 獵鯨呼喊 | 獵鯨呼喊 | 單發高傷 |
| 駱駝詛咒 | 駱駝詛咒 | 削弱：降護甲、降攻 |
| 象鳴 | 象鳴 | 多段、波及、打斷 |

組成規則：

- 一個法術由 1–5 張殘頁串接；**所有殘頁必須同韻**（原典「每行押同一個怪韻」）。韻為 3 種，是組合限制，也是圖示上的識別記號。
- **行數即法術等級**，不另設等級數值。第 N 行貢獻第 N 個效果層，依序結算。等級提升因此必然是質變（多一層行為），不可能退化成傷害倍率。
- 魔力成本 = 行數。詠唱回合：1–2 行即時；3–4 行詠唱 1 回合；5 行詠唱 2 回合。

單一組成系統同時承擔「蒐集」「成長」「配裝」「等級」，不引入第二套進度數值。

### 3. 難度來自機制與章節深度，不來自等級縮放

敵方數值 SHALL NOT 隨玩家等級、法術行數或章節進度等比例放大。等比縮放會抵銷成長體感，使玩法在數字變大後維持不變，是本輪要解決的問題本身的另一種形式。

難度改由兩者提供：章節深度對應固定的敵人名單；每隻敵人要求特定解法。以現有七隻改造，不新增定義：

| 敵人 | 新機制 | 逼出的配裝 |
| --- | --- | --- |
| 無名怨魂 | 非實體：僅死語成分能造成傷害 | 必須帶死語 |
| 織索巨蛛 | 每回合疊一層束縛，達上限即敗 | 速攻；長詠唱有風險 |
| 空鎧騎士 | 高護甲，未降甲時傷害趨近 0 | 必須帶駱駝詛咒 |
| 鐵脊龍鱷 | 反傷：每一效果層反彈固定傷害 | 短法術優於長法術 |
| 墓地魔狼 | 打斷者：其攻擊會中斷詠唱 | 不能在其面前長詠唱 |
| 深淵守龍 | 保留現有尾擊穿透可由格擋抵消 | 讀意圖並格擋 |
| 夢魘巫師・加茲納克 | 保留移首破綻與反咒需求，並綜合上述考驗 | 綜合 |

深淵守龍的「未格擋時額外穿透 4」是 v2 中唯一真正需要回應意圖的機制，方向正確，予以保留並推廣至全體。

意圖序列 SHALL 由 `run.random` 抽取，且各敵人意圖數不再一律為 3。介面 SHALL 繼續顯示下一個意圖：目標是消除背誦，不是消除資訊。

### 4. 施法代價用詠唱回合，不用失敗率

參照 Dungeon Crawl Stone Soup 的前提：施法之所以構成決策，是因為同時付出回合、魔力與失敗風險三種代價。v2 的技能三者皆無（與普攻同為一回合、格擋白回 3 魔、必定成功），因此不是決策而是按鈕。

本輪以詠唱回合承擔回合成本，並讓格擋回魔降為 1，使魔力成為真資源。**不採用機率失敗率**，理由是它與決策 5 的確定性重來衝突：章節重來若為位元級相同，玩家的最優解會變成記憶亂數序列而非理解戰鬥。詠唱改為可預判的風險——是否敢在打斷者面前起手，由玩家讀意圖決定——保留了失敗的可能性，且失敗歸因於判斷而非擲骰。

詠唱中被帶 `interrupt` 的意圖命中時，法術失效並退還一半魔力（向下取整）。詠唱狀態 SHALL 在戰鬥結束時清除，不跨遭遇保留。

### 5. 章節快照連 PRNG 一併回溯

進入章節時 SHALL 快照整個 `run`（含 `run.random` 的 `value` 與 `calls`）。死亡時以該快照取代 `run`。

PRNG 一併回溯是防刷的關鍵，不是實作細節。若重來時 PRNG 繼續前進，玩家可藉由故意死亡重骰掉落與事件，這正是 `contentValidation.ts:58` 以禁止環所防堵的行為。連同 PRNG 回溯後，重來的章節在敵人、事件與掉落上位元級相同，重骰在結構上不可能發生，原本由 DAG 承擔的防刷責任得以明確轉移。

此設計有一個被採納的副作用：同樣的打法必然導致同樣的死亡，玩家唯一能改變的是法術配裝。死亡因此從運氣事件變成配裝謎題，並使法術書成為承載遊戲的核心，而非附加系統。

由於重來為確定性，硬卡死時沒有其他出路，因此「全部重來」SHALL 永遠可用，作為必要逃生口而非便利功能。本輪一趟自足，全部重來即開新趟；`profile` 只保留歷史紀錄，不保留能力（見 Open Questions 1）。

### 6. 砍除場景敘述，擴充規則文字

刪除 `paragraphs` 與 `variants`（合計 6,909 字）。保留並擴充選項與規則文字（4,343 字）。

依據是實測的閱讀行為：選項 `detail` 已完整寫出結果，場景敘述因此不帶任何影響決策的資訊，跳過閱讀是最優解。本輪的正確操作不是減少文字總量，而是把文字預算從敘述移到規則——法術成分、韻、詠唱、打斷與敵人解法都必須在介面上講清楚，否則配裝無從判斷。總字數可能不減反增。

`npm run rpg:text` 與 `docs/rpg-story.md` 在敘述砍除後失去對象，SHALL 一併移除或改寫，不得留下會產生空稿的指令。`provenance` 契約改為記錄規則素材的原典出處（如四十行咒語的成分與韻），不再逐節記錄敘述出處。

### 7. 驗收改為可計算指標

v2 的 task 9 需要六位參與者各最多 180 分鐘並交叉測試，現有資源下無法執行；task 10.3 又禁止在無證據時勾選，使該 change 結構上無法結案。本輪撤回真人門檻與時長主張，改以引擎可重現的指標驗收：

| 指標 | 定義 | 門檻 |
| --- | --- | --- |
| 決策回合佔比 | 戰鬥回合中存在 ≥2 個結果不同的合法行動者 | ≥ 60% |
| 無主宰策略 | 對固定策略集合（純攻、純技、交替、貪婪等）逐一模擬全章節 | 每個固定策略至少在一章失敗 |
| 敵人分化 | 每隻敵人存在兩組配裝，其獲勝回合數差異 | ≥ 30% |
| 重來的資訊價值 | 每章存在配裝 A 失敗且配裝 B 成功的實例 | 每章至少一組 |

「無主宰策略」是本輪診斷所用模擬的常設化：該模擬在 v2 上會失敗（技能優先 21/21 勝），因此它能防止同一個問題再次通過驗收。指標 SHALL 由 `run.random` 驅動、可重現，不得使用 `Math.random()`。

有效決策 SHALL 由故事圖與戰鬥狀態計算，不得沿用 v2 以人工字串陣列長度代表決策數的做法（`test/rpg/routeMatrix.ts` 的 28／32 個「有效決策」中包含四個純進入戰鬥的項目，與 v2 spec 自訂的「純繼續不充數」相抵觸）。

### 8. 美術分階段，規則先行

第一階段不產出新圖，先用好既有的 1.4MB 圖集：

- 修正 6 處錯配：無名怨魂（顯示月亮）、空鎧騎士（與戰士、薩克諾斯共用劍）、墓地魔狼（顯示墓地小路）、療傷藥（顯示綠火）、盟約繩結（顯示城堡）、燭淚鏡（顯示書）。
- 放大顯示。原圖每格 313×313，目前渲染為 48px（`rpg.css:64`），僅使用 2.3% 像素。戰鬥主視覺改為放大呈現。
- 砍除戰士與遊俠釋出 2 格；第 12 格（墓地小路）與第 14 格（城堡）實為場景圖，改作章節背景。

殘頁圖示需求另列清單，屬第二階段，不阻擋規則驗收。美術產能是本方向的真正瓶頸：規則改動以週計，圖集擴充以月計，因此順序必須是規則先行、確認玩法改善後再投入繪製。

## Risks / Trade-offs

- **v2 約七成產出作廢。** 64 節故事圖、6,909 字敘述、三職業六專精、12 條路線矩陣與兩條 validator 規則都不再適用。存活的是引擎架構、序列化 PRNG、持久化與離線能力。此代價已知且被接受，因為作廢的正是造成重複的部分。
- **詠唱回合可能拖慢戰鬥。** 若每場都在等詠唱，節奏會比 v2 更差。緩解：1–2 行法術即時發動，長法術是可選的高風險路線而非必經流程；以決策回合佔比指標監看。
- **確定性重來可能硬卡死。** 配裝不足以通過某章時，重來結果恆定。「全部重來」是唯一出口，因此不可移除。若實測顯示卡死頻繁，再考慮在連續失敗後提供額外殘頁，屬後續調整。
- **砍職業降低初次選擇感。** 開局不再有三選一。緩解：以首批殘頁的選擇取代，使第一個決策仍然存在且更貼近核心系統。
- **美術瓶頸未解。** 若第二階段無法產出殘頁圖示，法術書會停在文字清單。第一階段的設計刻意不依賴新圖，使規則層仍可獨立驗收。
- **時長未證明。** 本 change 不主張三小時或任何時長。v2 的「約三小時」主張隨 `rpg-long-session-validation` 一併撤回，不以內容量換算時數。

## Migration Plan

1. `schemaVersion: 3`、`contentVersion: spell-research-1`。`persistence.ts` 現行僅接受 schema 2 且拒絕「非空 profile + `run: null`」，該 invariant 須明確改寫以容許退休遠征後的狀態。
2. 已知合法的 v1／v2 存檔以唯讀方式辨識，提供轉換預覽。確認後保留歷史紀錄（遠征次數、勝利數、已見記錄），退休既有 `run`，不以新規則續接舊戰鬥。v2 的永久升級在本輪無對應能力，SHALL 明示告知不再生效，不靜默丟棄。
3. 取消、重複確認、寫入失敗、讀取受阻、損毀與未知版本皆不得覆寫原始資料。沿用 `sudoku-drill-rpg-v1` key，不觸及其他遊戲的 key。
4. 章節快照使存檔約增為兩倍（783 → 約 1,488 字元），`deserializeGame` 的 100,000 字元上限有充足餘裕；`validGame` 須同時驗證 `run` 與 `checkpoint` 的合法性與 PRNG 狀態。

## Open Questions

1. **跨趟養成是否要回來。** 本輪定為一趟自足、無永久升級。若實測顯示需要長線目標，屬後續的加法變更，不影響本輪結構。
2. **章節數與每章遭遇數。** 暫定 5 章，實際數量須以決策回合佔比與實測節奏決定，本文件不預先固定。
3. **殘頁圖示的產製方式。** 第二階段需要 20 格以上新圖，產製管道尚未確定；在確定前不應承諾法術書的視覺規格。
4. **韻的數量。** 暫定 3 種。過少會使組合限制形同虛設，過多會讓殘頁難以湊齊，須以實測配裝可行性調整。
